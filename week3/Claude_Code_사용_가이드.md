# Claude Code 사용 특징 가이드

**인공지능서비스개발II · AI Agentic Coding 방법론 — 보충 핸드아웃**

대상: Claude Code가 처음인 학생 / 관련 실습: mini-todo-web 스타터 / 참고: 2부. Claude Code 제대로 이해하기

챗봇처럼 대화만 하던 Claude가 여러분의 프로젝트 파일을 직접 읽고 고치는 에이전트가 될 때 달라지는 것들을 정리했습니다. 앞의 다섯 가지는 에이전트로서 **동작하는 방식**이고, 뒤의 세 가지는 그 동작을 여러분이 **직접 다루는 도구**입니다.

> **왜 챗봇과 다른가.** 웹이나 앱에서 써본 Claude는 물어보면 텍스트로 답할 뿐, 여러분 컴퓨터의 파일에는 손을 대지 못합니다. Claude Code는 지금 열려 있는 프로젝트를 실제로 읽고 고치고 실행까지 해보는 "에이전트" 모드입니다. 이 전환이 오늘 핸드아웃의 핵심입니다.

## 이 핸드아웃에서 다루는 8가지

1. 파일을 직접 읽고 쓴다
2. 계획·실행·관찰 루프로 명령을 실행한다
3. 권한 요청으로 통제권은 사람에게 있다
4. 한 번의 지시로 여러 단계를 처리한다
5. 결과는 항상 되돌릴 수 있다
6. CLAUDE.md — 프로젝트 맥락 기억
7. 슬래시 커맨드 — 세션 관리
8. Skill — 반복 작업 패키징

---

## Part 1. 에이전트로서 동작하는 방식

도구 이름을 몰라도 이미 벌어지고 있는 것들 — Claude Code를 처음 켜는 순간부터 나타나는 특징입니다.

### 1. 파일을 직접 읽고 쓴다

지금 열려 있는 프로젝트 폴더의 파일을 실제로 열어보고, 수정하고, 새로 만듭니다. 사람이 코드를 복사해서 붙여넣을 필요가 없습니다.

- 예: "이 페이지에 버튼 하나 추가해줘" → `index.html`과 `app.js`를 직접 열어 수정

### 2. 계획 → 실행 → 관찰 루프로 명령까지 스스로 실행한다

목표 하나를 받으면 "무엇을 할지 계획 → 파일 수정·명령 실행 → 결과 확인 → 다시 계획"을 작업이 끝날 때까지 반복합니다. 테스트 실행, 패키지 설치 같은 명령도 스스로 실행하고 에러 메시지나 통과 여부까지 관찰해서 다음 행동을 판단합니다.

- 비유: 자동완성은 옆에서 다음 단어를 알려주는 사람이라면, Claude Code는 "이 작업 좀 해줘"라고 맡기면 알아서 파일을 열어보고 고치고 실행해보고 확인까지 하는 신입 개발자입니다.

### 3. 권한 요청으로 통제권은 사람에게 있다

파일을 고치거나 명령을 실행하기 전에 "허용(Allow)?"을 물어보는 게 기본값입니다. 매 단계 확인하며 진행할 수도 있고(Manual), 계획만 세우게 하거나(Plan), 알아서 전부 진행하게(Auto) 모드를 바꿀 수도 있습니다.

- 의미: "믿고 맡기되 검증한다"는 태도가 도구 설계 자체에 들어 있습니다.

### 4. 한 번의 지시로 여러 단계를 처리한다

"파일 열어서 → 이 부분 고치고 → 테스트 돌리고 → 결과 알려줘"를 일일이 시키지 않아도, "이 기능 추가해줘" 한 마디로 그 하위 단계들을 스스로 쪼개서 진행합니다. 다만 지시가 모호하면 엉뚱하게 해석할 수도 있어, 목표·입출력 예시·제약을 명확히 줄수록 결과가 안정적입니다.

- 주의: 편하다고 대충 시키면("바이브 코딩") 프로토타입에는 괜찮지만, 중요한 작업일수록 작게 쪼개고 명확하게 지시하는 습관이 필요합니다.

### 5. 결과는 항상 되돌릴 수 있다

버전 관리(git) 위에서 동작하기 때문에, 마음에 안 드는 결과가 나와도 변경 전으로 되돌릴 수 있습니다. 결과를 맹신하지 말고 `git diff`로 변경 사항을 훑어보며 의도치 않은 파일 변경은 없는지 확인하는 습관이 이 안전망을 실제로 쓰는 방법입니다.

- 실습 연계: GitHub Desktop의 Changes 탭으로 변경 파일을 확인하고, 마음에 안 들면 되돌리기(Discard/Revert)를 눌러보는 것도 같은 원리입니다.

## Part 2. 그 동작을 다루는 도구 3가지

Part 1의 특징들은 저절로 작동하지만, 결과 품질은 여러분이 이 세 도구를 얼마나 쓰느냐에 따라 크게 달라집니다.

### 6. CLAUDE.md — 프로젝트 맥락 기억

프로젝트 폴더 최상단에 두는 마크다운 파일 한 장. Claude Code는 세션을 시작할 때마다 이 파일을 자동으로 읽어들입니다 — 말하자면 에이전트가 처음 출근한 날 책상 위에 놓여 있는 "프로젝트 설명서"입니다.

**왜 필요한가요**

CLAUDE.md 없이 "이 페이지에 버튼 하나 추가해줘"라고 시키면, 에이전트는 이 프로젝트의 네이밍 규칙도, 테스트를 어떻게 돌리는지도, 어떤 파일을 건드리면 안 되는지도 모른 채 짐작으로 작업합니다. 매번 말로 설명하는 대신 한 번 적어두면, 이후 모든 세션이 같은 전제에서 시작됩니다.

**무엇을 적나요**

- 프로젝트 목적 — 한 줄이면 충분합니다
- 파일 구조 — 어떤 파일이 무슨 역할을 하는지
- 코딩 컨벤션 — 네이밍 규칙, 스타일
- 테스트 실행 방법 — `npm test` 같은 명령
- 건드리면 안 되는 것 — 하위 호환을 지켜야 할 부분

예시 — mini-todo-web용 CLAUDE.md:

```
# 프로젝트 개요
바닐라 HTML/CSS/JS로 만든 할 일 관리 웹페이지.

# 파일 구조
- index.html   : 화면 구조
- style.css    : 스타일
- todoLogic.js : 할 일 목록을 다루는 순수 함수들
- app.js       : 화면(DOM)과 todoLogic.js를 연결

# 코딩 컨벤션
- 함수/변수명은 camelCase
- 새 기능은 todoLogic.js에 추가하고 tests/에 테스트도 추가

# 테스트
- npm test (Jest)

# 건드리면 안 되는 것
- 기존 할 일 데이터 구조(스키마)는 유지
```

**만들고 확인하는 법**

직접 타이핑해도 되고, 채팅창에 `/init`을 입력하면 Claude Code가 코드베이스를 분석해서 초안을 자동으로 만들어 줍니다. 이후 `/context`를 실행하면 지금 세션의 "Memory files" 목록에 CLAUDE.md가 실제로 로드됐는지 확인할 수 있고, 내용을 고치고 싶을 땐 `/memory`를 씁니다.

> **TIP** CLAUDE.md는 "무엇을 만들지"를 적는 명세서가 아니라 "어떻게 짜야 하는지"를 적는 규칙서입니다. 무엇을 만들지는 REQUIREMENTS.md 같은 별도 문서의 몫입니다.

### 7. 슬래시 커맨드 — 세션 관리

`/`로 시작하는 내장 명령어. 코드가 아니라 "지금 이 대화 세션을 어떻게 다룰지"를 여러분이 직접 조작하는 조종간입니다. 채팅창에 `/`만 입력해도 지금 쓸 수 있는 목록이 자동완성으로 뜨기 때문에 외울 필요는 없습니다.

**자주 쓰는 커맨드**

| 커맨드 | 하는 일 | 언제 쓰나요 |
|---|---|---|
| `/clear` | 대화 맥락을 완전히 비우고 새로 시작 | 이전 작업과 무관한 새 작업을 시작할 때 |
| `/compact` | 길어진 대화를 요약해 컨텍스트 절약 | 대화가 길어져 응답이 느려지거나 헷갈릴 때 |
| `/model` | 사용할 모델 전환 | 더 빠르거나 더 신중한 모델이 필요할 때 |
| `/context` | 지금 세션에 로드된 것(메모리 파일 등) 확인 | CLAUDE.md가 실제로 반영됐는지 점검할 때 |
| `/init` | 코드베이스를 분석해 CLAUDE.md 초안 생성 | 처음 CLAUDE.md를 만들 때 |
| `/memory` | 메모리 파일 목록을 보고 편집 | CLAUDE.md 내용을 고칠 때 |
| `/help` | 전체 커맨드 메뉴 보기 | 뭐가 있는지 잘 모를 때 |

**왜 신경 써야 하나요**

대화가 길어질수록 에이전트가 참고해야 할 맥락도 늘어나 응답이 느려지거나 엉뚱한 이전 맥락을 끌어올 수 있습니다. 슬래시 커맨드는 "이 세션에 무엇이 담겨 있는지"를 여러분이 눈으로 확인하고, 필요할 때 비우거나 요약할 수 있게 해주는 계기판입니다.

> **TIP** 새로운 작업을 시작하기 전 `/clear`를 습관화하세요. 이전 작업의 맥락이 남아 있으면 관련 없는 코드까지 참고해 엉뚱한 결과를 낼 수 있습니다.

### 8. Skill — 반복 작업 패키징

채팅창에 매번 붙여넣던 지침을 `SKILL.md` 파일 하나로 저장해두는 기능. 저장해두면 대화 맥락이 맞을 때 Claude가 알아서 불러 쓰거나, `/스킬이름`으로 직접 호출할 수 있습니다.

**구조**

예시 — `.claude/skills/pr-checklist/SKILL.md`:

```
---
description: PR을 올리기 전에 체크리스트를 확인한다
---

## PR 체크리스트
1. 테스트가 모두 통과하는지 확인
2. 커밋 메시지가 컨벤션을 따르는지 확인
3. 변경 파일 목록에 의도치 않은 파일이 없는지 확인
```

맨 위 `description`은 "언제 이 Skill을 써야 하는지"를 짧게 적는 자리입니다. Claude는 지금 나누는 대화가 이 설명과 관련 있어 보이면 스스로 판단해서 불러 씁니다. 그 아래는 실제로 따라야 할 지침을 마크다운으로 적습니다.

**저장 위치와 호출 방법**

- `~/.claude/skills/` — 어떤 프로젝트에서든 나만 쓰는 개인용
- `.claude/skills/` — 이 프로젝트에서만 함께 쓰는 프로젝트용
- 자동 호출 — 대화 맥락이 description과 맞으면 알아서
- 수동 호출 — `/스킬이름`으로 직접 지정

> **TIP** CLAUDE.md가 "이 프로젝트의 규칙"이라면, Skill은 "내가 자주 시키는 절차"를 저장하는 것이라고 구분하면 헷갈리지 않습니다. "PR 만들 때 체크리스트"를 한 번 Skill로 만들어두면, 이후엔 `/pr-checklist` 한 마디로 끝입니다.

## 도구 3가지, 한눈에 비교

Part 1의 다섯 가지 특징은 도구 없이도 항상 작동합니다 — 아래 비교는 Part 2의 세 도구에 한정됩니다.

| | CLAUDE.md | 슬래시 커맨드 | Skill |
|---|---|---|---|
| 정체 | 프로젝트 설명서 파일 1개 | 세션을 조작하는 내장 명령어 | 절차를 담은 파일(SKILL.md) |
| 기억하는 것 | 이 프로젝트의 규칙 | 지금 대화의 상태 | 내가 자주 시키는 절차 |
| 불러오는 시점 | 세션 시작 시 자동 | 필요할 때 즉시 입력 | 대화 맥락에 맞을 때 자동, 또는 직접 호출 |
| 저장 위치 | 프로젝트 루트 | —(내장 기능) | `~/.claude/skills/` 또는 `.claude/skills/` |
