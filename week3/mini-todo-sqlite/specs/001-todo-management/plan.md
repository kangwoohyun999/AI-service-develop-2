# Implementation Plan: Todo Management

**Branch**: `001-todo-management` | **Date**: 2026-09-16 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-todo-management/spec.md`

## Summary

Deliver add / list / toggle-complete / delete for todos ("tasks") as a single Next.js App Router
application: a REST API under `app/api/tasks` backed by Prisma ORM against a local SQLite file
(`dev.db`), plus a page that consumes that API. No external services, accounts, or separate
backend/server process are required — everything runs from `npm run dev` against a local file.

## Technical Context

**Language/Version**: TypeScript 5.9 (strict mode), Node.js 24 runtime (as installed; Next.js 16
requires Node 20.9+)

**Primary Dependencies**: Next.js 16 (App Router), React 19, Prisma ORM 7.10.0 + `@prisma/client`
+ `@prisma/adapter-better-sqlite3` (driver adapter, required by Prisma 7's client API), `dotenv`
(dev-only, for the Prisma CLI's config file), Tailwind CSS 4 (already scaffolded, for the list UI)

**Storage**: SQLite, single local file `prisma/dev.db`, accessed exclusively through Prisma Client
(no raw SQL)

**Testing**: Vitest for API route-handler contract tests and integration tests (see
[research.md](./research.md) for rationale)

**Target Platform**: Local Node.js server via `next dev` / `next start`; no hosting, container, or
external service dependency

**Project Type**: Single Next.js App Router project (UI + API routes co-located) — not a
frontend/backend split

**Performance Goals**: No special targets beyond spec's SC-003/SC-004 (<1s perceived update after
toggle/delete); trivial for local SQLite reads/writes at this scale

**Constraints**: No authentication/authorization (single-user, per spec Assumptions); no offline
mode required; no separate server process or third-party account signup (per user instruction)

**Scale/Scope**: Single user, single device, expected tens to low hundreds of tasks; 2 route files,
4 HTTP operations (GET, POST, PATCH, DELETE), 3 user stories

### Source Code (repository root)

```text
app/
├── layout.tsx                  # existing root layout
├── page.tsx                    # todo list UI: add form, list, toggle, delete
├── globals.css                 # existing Tailwind styles
└── api/
    └── tasks/
        ├── route.ts            # GET (list all tasks), POST (create task)
        └── [id]/
            └── route.ts        # PATCH (toggle completion), DELETE (remove task)

lib/
└── prisma.ts                   # Prisma Client singleton (hot-reload safe)

prisma/
├── schema.prisma                # Task model (id, title, completed, createdAt)
├── migrations/                  # generated by `prisma migrate dev`
└── dev.db                       # local SQLite file (generated, gitignored)

tests/
├── contract/
│   └── tasks-api.test.ts        # request/response shape tests per contracts/tasks-api.md
└── integration/
    └── todo-management.test.ts  # one test per user story acceptance scenario
```

**Structure Decision**: Single Next.js App Router project. UI (`app/page.tsx`) and REST API
(`app/api/tasks/**`) are co-located in the same app, matching the user's explicit routing choice
and Constitution Principle I. Prisma isolates all database access behind `lib/prisma.ts` and
`prisma/schema.prisma`; no separate backend service or repository layer is introduced since the
scope (single entity, four operations) doesn't justify one.
