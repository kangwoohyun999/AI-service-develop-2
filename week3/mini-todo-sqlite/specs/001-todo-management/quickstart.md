# Quickstart: Todo Management

Validates the feature end-to-end against [spec.md](./spec.md)'s user stories, using the contract
in [contracts/tasks-api.md](./contracts/tasks-api.md) and the model in
[data-model.md](./data-model.md).

## Prerequisites

- Node.js 20.9+ (project uses Node 24)
- Dependencies installed: `npm install`
- Prisma + `@prisma/client` added and the SQLite datasource configured per
  [data-model.md](./data-model.md#prisma-schema-sketch)

## Setup

```bash
npm install                          # installs prisma, @prisma/client, @prisma/adapter-better-sqlite3, dotenv
npx prisma migrate dev --name init   # creates prisma/dev.db and applies the Task model
npx prisma generate                  # emits generated/prisma (not run automatically by migrate dev)
npm run dev                          # starts the app at http://localhost:3000
```

Requires a `.env` file at the repo root with `DATABASE_URL="file:./prisma/dev.db"` (already
gitignored). Note: the path is resolved relative to the process's working directory (the repo
root), not relative to `schema.prisma` — `file:./dev.db` would create the database file at the
repo root instead of inside `prisma/`.

## Validate User Story 1 — Add and view todos (P1)

1. Open `http://localhost:3000` — the list is empty (spec Edge Cases: empty list).
2. Add a task titled "우유 사기" via the UI, or directly:
   ```bash
   curl -s -X POST http://localhost:3000/api/tasks \
     -H "Content-Type: application/json" \
     -d '{"title":"우유 사기"}'
   ```
   **Expected**: `201`, `{ "data": { "id": 1, "title": "우유 사기", "completed": false, ... } }`.
3. Refresh the page (or `GET /api/tasks`) — the task appears in the list with "not completed"
   status. **Expected**: satisfies FR-001, FR-003, FR-004, SC-001, SC-002.
4. Attempt to add a task with an empty/whitespace title:
   ```bash
   curl -s -X POST http://localhost:3000/api/tasks -H "Content-Type: application/json" -d '{"title":"   "}'
   ```
   **Expected**: `400`, `{ "error": "Title is required" }`, and the list is unchanged (FR-002).

## Validate User Story 2 — Toggle completion status (P2)

1. Toggle the task created above:
   ```bash
   curl -s -X PATCH http://localhost:3000/api/tasks/1
   ```
   **Expected**: `200`, `completed: true`. Toggling again returns `completed: false`
   (FR-005, SC-003).

## Validate User Story 3 — Delete a todo (P3)

1. Delete the task:
   ```bash
   curl -s -X DELETE http://localhost:3000/api/tasks/1
   ```
   **Expected**: `200`, `{ "data": { "id": 1 } }`; the task no longer appears in `GET /api/tasks`
   (FR-006, SC-004).
2. Repeat the same `DELETE` call. **Expected**: `404`, `{ "error": "Task not found" }`, and any
   other existing tasks are unaffected (FR-008).

## Validate User Story 4 — Set and change priority (P2)

1. Add a task without specifying a priority:
   ```bash
   curl -s -X POST http://localhost:3000/api/tasks -H "Content-Type: application/json" -d '{"title":"기본 우선순위"}'
   ```
   **Expected**: `201`, `"priority": "MEDIUM"` in the response (FR-009).
2. Add a task with an explicit priority:
   ```bash
   curl -s -X POST http://localhost:3000/api/tasks -H "Content-Type: application/json" -d '{"title":"급한 일","priority":"HIGH"}'
   ```
   **Expected**: `201`, `"priority": "HIGH"`.
3. Attempt to create a task with an invalid priority:
   ```bash
   curl -s -X POST http://localhost:3000/api/tasks -H "Content-Type: application/json" -d '{"title":"이상한 일","priority":"URGENT"}'
   ```
   **Expected**: `400`, `{ "error": "Invalid priority" }`, and nothing is created.
4. Change an existing task's priority (using the id from step 1):
   ```bash
   curl -s -X PATCH http://localhost:3000/api/tasks/1 -H "Content-Type: application/json" -d '{"priority":"LOW"}'
   ```
   **Expected**: `200`, `"priority": "LOW"`, and `completed` is unchanged (FR-010, SC-006).
5. Confirm the no-body toggle still works after the above (regression check):
   ```bash
   curl -s -X PATCH http://localhost:3000/api/tasks/1
   ```
   **Expected**: `200`, `completed` flips; `priority` is unchanged.
